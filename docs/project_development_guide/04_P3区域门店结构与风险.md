## W025 P3-A 城市指标与两种缺货口径

### 工作背景

P1/P2 之后，项目要做区域对比。城市对比看似简单，但“缺货率”有两个完全不同的口径。

### 输入

`clean_train`、`agg_city_summary`、`agg_store_summary`。

### 实际步骤

1. `city_core` 按城市聚合总指数、门店数、单店日均、缺货、促销；
2. 计算 SKU-日缺货率：有缺货 SKU-日 / 总 SKU-日；
3. 计算小时槽位缺货率：缺货小时 / (16 × SKU-日)；
4. `city_category_stats` 计算城市类别结构；
5. 输出 `a1_city_metrics`。

### 核心原理

SKU-日率回答“多少商品-天出现过缺货”；小时率回答“营业时间里缺货占多久”。一个高、一个低，不能互换。

### 产物

`a1_city_metrics.csv`（18 行）、`a2_city_category.csv`、`a3_city_store_distribution.csv`。

### 运行实例（真实口径）

P3-A 的 `stockout_sku_day_rate` 是城市内门店率的简单平均；`stockout_day_rate` 才是池化率。P3-D 后来明确：P3-A 同名字段与 P3-B/C/D 不同义。

### 遇到的问题

同名不同义：P3-A 的 `stockout_sku_day_rate` 与 P3-B/C/D 的同名字段计算方式不同。

### 验证

`test_p3_city.py::test_city_core_denominators`、`test_city_sku_per_store_and_category`。

### 下游

W026 城市分布/小城市；BI 城市页。

## W026 P3-A 城市分布、小城市与 bootstrap

### 工作背景

城市之间不仅要比均值，还要看内部离散、集中度与相关性稳定性。

### 实际步骤

1. `store_distribution` 计算城市内门店 P10/P25/P75/P90、Top10% 份额、CV；
2. 门店数 <10 的城市只展示、不排名（5 个）；
3. `correlation_table` 用 1,000 次 percentile bootstrap 计算 Spearman CI，`seed=42`；
4. `city0_sensitivity` 剔除 City 0（290 店）做对照；
5. 输出 `a4` 与 f1–f6。

### 核心原理

小样本排名不稳定；bootstrap 用重采样估计不确定性，比单点相关更可信。

### 产物

`a3_city_store_distribution`、`a4_city_category_long`、相关性表、敏感性表。

### 运行实例

City 0 有 290 家门店，占 898 的 32.3%，对整体相关影响大；敏感性分析专门剔除它看结论是否稳定。

### 遇到的问题

bootstrap 样本量与城市内门店数相关；文档中 P3-C 与 P3-D 对样本量区间有不同记录（207–1,894 vs 218–1,983），属于文档不一致。

### 验证

`test_p3_city.py::test_finalize_small_city_and_ranks`、`test_bootstrap_metadata`。

BI 城市对比表（W052）。

## W027 P3-B 门店 RLM 建模

### 工作背景

门店规模不同，直接比销量不公平。需要控制规模后的“相对效率”。

### 输入

`agg_store_summary`、`c1_store_structure`（后续）。

### 实际步骤

1. `model_frame` 取 `SKU≥10` 的门店；
2. `x = log(sku_count)`，`y = log1p(per_sku_day_index)`；
3. `fit_rlm` 用 Huber（`M=1.345`）拟合；
4. 计算斜率、标准误、95% CI、残差、权重；
5. 同时跑 OLS 与中位数回归做对照。

### 核心原理

Huber 回归对残差大的点使用线性损失，降低异常门店对斜率的影响。取对数是因为销量与 SKU 数都是长尾分布。

### 产物

`b1_store_metrics`、`b2_model_comparison`、`b3_diagnostics`。

### 运行实例（关键代码）

```python
res = sm.RLM(y, X, M=HuberT(t=1.345)).fit()
slope = float(res.params[1])
ci_low, ci_high = slope - 1.96*se, slope + 1.96*se
```

### 遇到的问题

稳健回归的“R²”不是标准 R²；报告曾写 `R²_weighted=0.119`，后来改名“加权拟合指数”。

### 验证

`test_p3b_store.py::test_r2_definitions`、`test_p3b_regression_numbers`。

### 下游

W028 四象限。

## W028 P3-B 四象限、敏感性与命名整改

### 工作背景

拟合出残差后，需要把门店分成“规模高/低 × 效率高/低”四类。

### 实际步骤

1. 规模轴：`per_day_index` 的 P50；
2. 效率轴：`eff_resid` 的 P50；
3. 高/低按 `>P50` / `<=P50`，并列归低；
4. 计算四象限画像；
5. 门槛敏感性：SKU≥5/10/20/30 → 897/888/808/681；
6. 审计后把 `R²_weighted` 改名“加权拟合指数”，结论降级为“弱拟合、仅探索性”。

### 核心原理

用中位数切分比均值更稳健；边界并列归低，避免“刚好 P50”被分到高效。

### 产物

`b4_quadrant`、`b5_threshold_sensitivity`、`b6_quadrant_profile`、`b7_typical_stores`。

### 运行实例（真实结果）

四象限门店数：**261 / 183 / 183 / 261**。

`R²_weighted=0.1194611254`，`R²_corr=0.0346`，高影响门店 48 家（5.41%），OLS 与 Huber 斜率差约 40%。

### 遇到的问题

“R²”名字让读者误以为拟合良好；≥30 一致率 82.23% 只在 681 家交集成立，207 家未参与。

### 验证

`test_quadrant_tie_goes_low`、`test_typical_store_selection_deterministic`；审计复核通过。

### 下游

P4-A 门店档案的 `quadrant`、BI 门店页。

## W029 P3-C SKU 与类别结构（HHI/熵）

### 工作背景

同样规模的门店，商品结构可能完全不同。需要量化集中度与分散度。

### 输入

`clean_train`、`agg_store_summary`。

### 实际步骤

1. `store_sku_structure` 用窗口函数取 Top1/Top5 份额，计算 SKU HHI；
2. `store_category_structure` 计算类别 HHI、熵、类别数；
3. `category_penetration` 计算类别覆盖门店数，稀有类别阈值 <10 店；
4. 输出 `c1`–`c3`。

### 核心原理

HHI = Σ(份额²)，对“多个中等 SKU”也敏感；熵 = -Σp·ln p，越大越分散。两者互补。

### 产物

`c1_store_structure`（898 行）、`c2_store_category_structure`、`c3_category_penetration`。

### 运行实例（真实数据）

门店 0：SKU HHI 0.023639，Top1 4.02%，Top5 15.99%，类别 HHI 0.115967，类别熵 2.472809，类别数 21。

### 遇到的问题

单店 SKU 的 HHI=1 会天然“集中”，所以商品侧风险旗标只在覆盖 ≥5 店时评估；门店结构侧不涉及这个问题。

### 验证

`test_store_sku_hhi_formula`、`test_p3c_regression_outputs`。

### 下游

W030 十分位/聚类；P4-A 结构字段。

## W030 P3-C 十分位、聚类与典型店

### 工作背景

需要按 SKU 覆盖数把门店分组，并找出结构相似的门店群。

### 实际步骤

1. `equal_size_deciles`：按 `sku_count, store_id` 排序，`np.array_split` 等样本量切 10 组；
2. `decile_stats`：每组算 HHI/规模中位数，`n<20` 标“样本不足”；
3. `prepare_vectors`：门店×类别份额矩阵，L2 归一化；
4. `linkage_and_clusters`：Euclidean + Ward，`fcluster(k=4)` → G1–G4；
5. `rare_sensitivity`：剔除稀有类别后算 ARI；
6. `typical_stores`：每组取离中心最近的门店。

### 核心原理

`qcut` 会把相同 SKU 数的门店切到不同组；`np.array_split` 先排序再等分，保证“同规模可比”。L2 归一化消除规模，只比较结构比例。

### 产物

`c4_store_deciles`、`c5_decile_stats`、`c6_cosine`、`c7_linkage`、`c8_cluster_assignments`、`c9_rare_sensitivity`、`c10_typical_stores`。

### 运行实例（真实结果）

结构群规模：G1=189、G2=181、G3=168、G4=350；剔除稀有类别后 ARI=1.000。

### 遇到的问题

`qcut` 残留写法在方案文档中出现过，与 `np.array_split` 冲突；属于文档残留，代码以 `np.array_split` 为准。

### 验证

`test_equal_size_deciles_no_loss_and_ties_split`、`test_l2_norm_unit_rows`。

### 下游

P4-A `cluster`、四象限×结构群 16 格（W037）。

## W031 P3-C 审计修正：行序、图片、抽样

### 工作背景

P3-C 审计发现 bootstrap CI 会随行序变化。

### 实际步骤

1. 复现：同一数据换行序，CI 从 −0.798734~−0.734246 变为 −0.801941~−0.735777；
2. 根因：bootstrap 抽样按数组顺序；
3. 修正：`_spearman_ci` 先按 `store_id` 排序；
4. 新增“行序不变性”测试；
5. 修正图片路径断链；
6. 抽样排除典型店。

### 核心原理

可复现 = 固定种子 + 固定输入顺序 + 固定实现。

### 产物

`p3c_structure.py:167-176`；新增测试 `test_spearman_ci_order_invariant`。

### 运行实例

```python
sid = np.asarray(store_ids)[mask]
order = np.argsort(sid, kind="mergesort")
x, y = x[order], y[order]
```

### 遇到的问题

固定 seed 不能解决行序问题；必须显式排序。

### 验证

44 → 45 passed；CI 稳定为 −0.801941~−0.735777。

### 下游

## W032 P3-D 风险标记 R1–R8

### 工作背景

需要把缺货、低销、零销、波动、异常日统一成可筛选的风险标记。

### 输入

`d1_store_risk_base`（898 行）、`c1/c4/c8`。

### 实际步骤

1. 限定风险样本：`structure_valid=True`（SKU≥10），888 家；
2. `thresholds` 计算 R1/R2/R4/R5/R6 的 P90、R7 的 P10；
3. R8 逐十分位计算 HHI P90；
4. `add_flags` 打标；
5. `stockout_domain=R1|R2`；`domain_count` 只算五个运营域；`multi_risk=domain_count>=2`。

### 核心原理

阈值不是拍脑袋：用全样本分位，保证每个域大约 10% 命中（R3 是规则阈值，R6 是离散值）。R7/R8 只作结构提示，不计入运营域。

### 产物

`d1_store_risk_base`、`d2_thresholds`、`d9_domain_count`。

### 运行实例（真实阈值与命中）

| 标记 | 阈值 | 命中 |
|---|---:|---:|
| R1 | P90 0.485532 | 89 |
| R2 | P90 0.223361 | 89 |
| R3 | ≥7 天 | 90 |
| R4 | P90 0.091657 | 89 |
| R5 | P90 0.298730 | 89 |
| R6 | P90 4/90 | 56 |
| R7 | P10 20 | 93 |
| R8 | 分位内 P90 | 90 |

### 遇到的问题

- R1 与 R2 不是同一批门店：交集 24，并集 154；
- R6 是离散值，严格 `>P90` 命中 56，`>=P90` 会命中 100；
- 10 家 SKU<10 的 R1–R8 必须为 NA，不能记 0/False。

### 验证

`test_p3d_risk.py::test_p3d_regression_outputs` 断言 89/89/90/89/89/56/93/90；`test_r8_threshold_is_within_decile`；`test_stockout_metric_bounds`。

## W033 P3-D 共现、精确/至少、审计与 P3 整体验收

### 工作背景

风险标记完成后，需要回答“哪些门店同时命中多个域”，并把 P3 整体验收。

### 实际步骤

1. `cooccurrence` 输出共现矩阵、两两“至少”、域数分布、Top10 精确；
2. `d8b` 生成 15 行（含 5 行同域对角线），后续 BI 过滤为 10 对；
3. `decomposition` 验证 `R2=R1×(平均缺货小时/16)`；
4. `sensitivity` 做 P85/P90/P95、minSKU 5/20/30、城市内 P90、剔除 City 0；
5. P4 阶段再把精确组合做成 16 种；
6. P3 整体验收补 D1–D17 指标字典。

### 核心原理

“至少”允许其他域；“精确”要求域集合完全相等。两者回答不同问题，不能相加/相减。

### 产物

`d8b_pairwise_combinations`、`d9_domain_count`、`d10`–`d13`、`summary.json`。

### 运行实例（真实结果）

- 运营域分布：0 域 581、1 域 175、2 域 101、3 域 25、4 域 4、5 域 2；
- 多风险 132 家（14.86%）；
- 至少组合“缺货+高零销”56 家；
- 精确组合“缺货+高零销”38 家（P4）。

### 遇到的问题与修正

1. **整体缺货率二次加权**：0.4434/0.2027 → 池化 0.442668/0.198771；
2. **54 家低销门店被 `fillna(0)`**：P3-D 独立复算 `low_run_max_days`；
3. **bootstrap 样本量硬编码**：修正为 218–1,983/中位 852；
4. **P3-A 同名不同义**：在 P3-D 报告中明确三种率（池化/城市/门店分布）。

### 验证

`test_p3d_risk.py` 9 个测试；P3 整体验收 54 passed；R1–R8 命中未变。
