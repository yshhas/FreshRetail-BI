# 00 项目全貌与阅读指南

> 本目录是一套“研发工作单元”级文档，不是阶段总结。每个工作单元都对应真实的文件、数据、接口、页面或测试，并回答：为什么做、开始前有什么、具体怎么做、原理是什么、产出什么、怎么验证、下游谁用。
>
> 证据等级：**A** = 文档/代码/数据/测试直接证明；**B** = 由实现与上下文合理推断；**C** = 现有材料无法确认。

## 一、项目是什么

**项目名**：中国数字零售与本地生活经营增长分析
**数据**：FreshRetailNet-50K（叮咚买菜，CC BY 4.0）
**最终形态**：一套本地只读零售经营 BI

它不是一个“万能经营平台”。它只做四类分析：

1. **销量经营**：整体趋势、异常日、门店差异、持续低销；
2. **商品经营**：SKU 规模/效率、覆盖、集中度、风险旗标；
3. **区域与门店**：城市对比、门店分层、商品结构、缺货与风险；
4. **经营诊断**：门店档案、风险组合、商品与门店联动。

然后把这些结果冻结，做成一个只读网站：

- 经营总览；
- 城市与门店；
- 经营风险（精确组合 / 至少组合）；
- 门店详情（SKU 列表）；
- 商品总览 / 列表 / 风险 / 类别 / 详情；
- 跨页面下钻与返回状态。

---

## 二、项目不是什么

- 不是金额/GMV/利润分析：数据的 `sale_amount` 是归一化销量，不是金额；
- 不是用户/复购/留存分析：数据没有用户 ID、没有订单 ID；
- 不是实时系统：没有消息队列、没有实时接入；
- 不是 AI/预测系统：没有模型训练、没有 Agent/RAG；
- 不是生产级 SaaS：没有鉴权、没有 Docker、没有公网部署、没有 CI。

这些“不是”不是遗漏，而是数据与项目边界共同决定的。

## 三、最终技术架构

```
浏览器
  React 18 + TypeScript + Vite + ECharts
  URL search params = 筛选状态
        │ GET /api/v1/*
        ▼
FastAPI（bi_api.main）
  Pydantic 响应契约 / 参数白名单 / CORS / 错误映射
        │ service.py 参数化 SQL
        ▼
DuckDB（内存连接，25 个只读视图）
  禁外部访问 / 限定 data 目录 / 只允许 SELECT
        │ read_parquet / read_csv_auto
        ▼
冻结数据（25 项 SHA-256）
  data/derived + data/analysis/p1–p4
```

启动顺序：

1. `freeze.verify_manifest()` 校验 25 个文件；
2. `ReadOnlyDB` 建 25 个视图；
3. FastAPI 开始接收请求；
4. 前端 Vite dev server（5173）把 `/api` 代理到 8000。

## 六、每个工作单元的写法

每个单元都尽量包含：

1. **工作背景**：为什么做；
2. **输入**：开始前有什么（文件/字段/表）；
3. **实际步骤**：一步步做了什么；
4. **核心原理**：技术/算法为什么这样；
5. **产物**：新增/修改了什么；
6. **运行实例**：真实数据/请求/页面走一遍；
7. **遇到的问题**：真实困难与处理；
8. **验证**：怎么证明；
9. **下游**：谁用、引出了什么。

不是每个单元都九项齐全，但重要单元不会缺。
