## W061 数据与分析测试

### 工作背景

数据项目的“正确性”不是页面能打开，而是数字与冻结值一致、边界行为正确。

### 输入

`tests/` 下 10 个测试文件、约 61 个测试函数。

### 实际步骤

1. 契约测试：文件元数据、schema、train/eval 切分、重叠报错；
2. 清洗测试：原始列不变、派生旗标、越界折扣、规则可追溯；
3. 指标测试：日/商品/城市/门店聚合、缺货梯度、促销配对、小时、天气、异常/健康度、16 槽契约；
4. P2：份额/排名、Pareto、覆盖敏感性、稳定性、单店 HHI 不误判、头尾、两种效率口径、跨层级一致、动态天数、审计数字、MAD=0；
5. P3-A/B/C/D：分母、小城市、bootstrap、R² 定义、象限、等样本十分位、HHI、行序不变、R1–R8 命中、缺货边界；
6. P4：898/888/10、精确 16、38/56、incidence 50,000、共现、16 格、无 score、无 eval。

### 核心原理

测试直接断言冻结数字，例如：

- 865 个 SKU；
- 117 个风险 SKU、35 个多风险；
- R1–R8 = 89/89/90/89/89/56/93/90；
- 精确 38 / 至少 56；
- incidence 总指数 4,493,660.787。

这样任何口径漂移都会立刻变红。

### 产物

`tests/test_contracts.py`、`test_cleaning.py`、`test_metrics.py`、`test_p2.py`、`test_p3_city.py`、`test_p3b_store.py`、`test_p3c_structure.py`、`test_p3d_risk.py`、`test_p4_diagnosis.py`。

### 运行实例（真实断言）

```python
assert at_least == 56
assert exact == 38
assert int(inc.observed_rows.sum()) == 4_500_000
assert inc.total_index.sum() == pytest.approx(4493660.787, abs=1e-3)
```

### 遇到的问题

测试与真实冻结数据强耦合；数据重冻结会导致大面积失败。这是“保护”也是“成本”。

### 验证

本轮 `python -m pytest -q`：**101 passed**。

### 下游

W062 BI 测试。

## W062 BI API、契约与安全测试

### 工作背景

BI 层新增了视图、路由、参数、抑制、只读安全，需要单独测试。

### 输入

`bi/tests/` 5 个文件、约 39 个测试函数。

### 实际步骤

1. `test_bi0_contracts.py`：manifest、重复 key、25 视图、KPI、城市/门店契约、SKU<10 不适用、抑制、只读、外部访问、无 eval；
2. `test_bi0_api.py`：health/trend、筛选、抑制、组合/导出、5 线程并发；
3. `test_bi2_products.py`：865 全量、向后兼容、overview 契约、筛选、详情一致、门店 incidence、共现、低覆盖抑制、白名单/注入、25 视图；
4. `test_bi2c_stores.py`：精确组合计数、非法、参数化、SKU 一致、flagged+分页、sort 白名单、404/小样本、默认不变；
5. `test_bi2c_c3_domains.py`：10 对“至少”全量比对、非法/互斥、注入/互斥、空值/默认。

### 核心原理

API 测试不只测 200，还测：

- 数字等于冻结值；
- 非法参数 400；
- 白名单回退；
- 小样本 `suppressed=true`；
- 不能读外部文件。

### 产物

`bi/tests/*.py`。

### 运行实例（真实断言）

```python
assert body["meta"]["n"] == int(row.stores_at_least)
assert all(r[a] is True and r[b] is True for r in body["data"])
assert client.get("/api/v1/stores", params={"domains": ""}).status_code == 400
```

### 遇到的问题

并发测试只有 5 线程，不能证明高并发安全；但能发现 RLock 基本问题。

### 验证

本轮 101 passed 包含 `bi/tests`；C-4 边界探针 21/21。

## W066 运行交付与项目边界

### 工作背景

项目最终要能在 Windows 11 本机展示，而不是只在开发环境里跑。

### 输入

后端 `bi/src/bi_api`、前端 `bi/web`、冻结数据、运行说明。

### 实际步骤

1. 只读检查环境：Node 24.16、Python 3.13.9、依赖版本；
2. 确认端口：8000 API、5173 dev、4173 preview；
3. 确认数据文件与 25 项 manifest；
4. 写启动步骤：
   - 后端：`$env:PYTHONPATH="bi/src"; python -m uvicorn bi_api.main:app --host 127.0.0.1 --port 8000`
   - 前端：`cd bi/web; npm run dev`
   - 预览：`npm run build; npm run preview`
5. 写展示路径：总览→城市→门店→SKU→商品→返回；风险精确/至少；商品五页。

### 核心原理

交付不是“代码在仓库里”，而是“别人能按步骤跑起来”。

### 产物

`09_BI平台本地展示与运行说明.md`。

### 运行实例（实测）

- API `/health` 200，`data_version=p1-p4-freeze-2026-11-08`；
- 前端 5173、预览 4173 均返回 200；
- 浏览器冒烟：总览 898、城市门店 20 行、风险 16 行、商品 865、商品详情 P0005、城市→门店→返回。

### 遇到的问题

- 无 Docker：换机需要 Python/Node 环境；
- 无公网：仅绑定 127.0.0.1；
- 无鉴权：不能多人/公网使用；
- 9 项依赖漏洞未升级；
- 无 CI：测试靠手动。

### 验证

运行说明中的命令与实际进程一致；浏览器冒烟 6 项通过。

### 下游

项目最终交付；后续若要生产化，需补 Docker/鉴权/CI/监控。
