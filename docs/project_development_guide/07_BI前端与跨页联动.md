## W048 前端工程与路由

### 工作背景

BI-0 只有 API，没有页面。需要一套前端工程承载 9 个业务页面。

### 输入

Vite + React 18 + TypeScript + ECharts；API 契约。

### 实际步骤

1. `npm create vite` 生成 React + TS 工程；
2. 配置 `vite.config.ts`：`host=127.0.0.1`、`port=5173`、`/api → 8000` 代理；
3. `main.tsx` 挂载 `<App />`；
4. `App.tsx` 用 `BrowserRouter` 定义路由；
5. `Layout` 提供左侧导航与顶部说明。

### 核心原理

Vite dev server 把 `/api` 代理到后端，浏览器端同源，避免 CORS；生产预览 4173 也用同一代理。

### 产物

`package.json`、`vite.config.ts`、`src/main.tsx`、`src/App.tsx`、`components/Layout.tsx`。

### 运行实例（实际路由）

```
/cities-stores
/products
/products/list
/products/risk
/products/categories
/products/:productId
/risk
/stores/:storeId
* → 页面不存在
```

9 个业务路由 + 1 个 404 兜底。

### 遇到的问题

设计方案的 `/cities`、`/stores` 合并成 `/cities-stores`；商品拆成 5 页；`/explore`、`/methodology` 未建。

## W049 URL 状态：`useUrlFilters`

### 工作背景

筛选、分页、组合必须刷新可恢复、可分享、可前进后退。

### 输入

React Router 的 `useSearchParams`。

### 实际步骤

1. `get(key, fallback)` 读取参数；
2. `set(key, value)` 写参数，空值删除；
3. 任何非 `page` 参数变化，删除 `page`；
4. 使用 `replace`，不污染历史；
5. `patch(obj)` 批量更新。

### 核心原理

URL 是唯一筛选真源；组件不保存筛选副本，避免“URL 和状态不一致”。

### 产物

`lib/useUrlFilters.ts`。

### 运行实例（关键代码）

```ts
if (key !== 'page') next.delete('page')
setParams(next, { replace: true })
```

### 遇到的问题

如果切换筛选不删 page，用户在第 3 页筛选出 1 页结果，会看到空表。

### 验证

`bi/tests`? 实际由 E2E `e2e.mjs` 的“filter resets page”验证；`test_bi0_api` 不涉及。

### 下游

全部筛选页面。

## W050 请求层：`client.ts` 与 `useApi`

### 工作背景

页面需要统一的请求、错误处理、加载态、卸载保护。

### 实际步骤

1. `qs` 丢弃 `undefined/null/''`；
2. `get` 拼 `/api/v1`，非 2xx 时解析 `detail` 抛错；
3. `useApi(loader, deps)` 管理 `data/loading/error/reload`；
4. `alive` 标志防止卸载后 `setState`。

### 核心原理

只读 GET 请求不需要缓存库；`useApi` 足够覆盖当前复杂度。

### 产物

`api/client.ts`、`lib/useApi.ts`。

### 运行实例（错误处理）

后端 400 `{"detail":"domains must not be empty"}` → 前端 `Error.message = "domains must not be empty"` → 页面 `ErrorBox`。

### 遇到的问题

没有请求去重/缓存；页面切换会重复请求。这是已知代价。

### 验证

`npm test` 的纯函数测试；E2E 的错误/加载态。

## W057 导航与返回：`returnTo` + `BackLink`

### 工作背景

C-2 增加“门店→SKU→商品”链路后，返回只能回一层。

### 实际步骤

1. `buildReturnTo(pathname, search)` 生成来源 URL，删除自身 `returnTo`；
2. `detailHref(path, returnTo)` 生成带参数的详情链接；
3. `safeReturnTo` 校验；
4. `BackLink`：有 `returnTo` 且 `location.key !== 'default'` → `nav(-1)`；否则跳 `returnTo`。

### 核心原理

浏览器历史本身就是导航栈；`returnTo` 只用于刷新/直达的降级。

### 产物

`lib/navigation.ts`、`components/BackLink.tsx`。

### 运行实例

`/stores/70?returnTo=%2Fcities-stores%3Fcity%3D3` → 返回城市页，`city=3` 保留。

`/products/4?returnTo=...` → 返回门店，再返回城市，链路完整。

### 遇到的问题

`returnTo` 嵌套会循环；删除嵌套会丢上层 context；最终用历史解决。

### 验证

`e2e-c1` 8/8、`e2e-c4` 多级返回 2 项。

### 下游

## W059 安全：`safeReturnTo` 与 S-01

### 工作背景

`returnTo` 是用户可编辑参数，可能被用于开放重定向、路径穿越、超长 URL。

### 实际步骤

1. 长度 ≤500；
2. 单 `/` 开头，拒绝 `//`、反斜杠；
3. 只取路径段，检查原始 `..`；
4. 最多解码 5 次，识别 `%2e%2e`、`%252e`、`%2f`、`%5c`；
5. `new URL` origin 校验；
6. 拒绝用户名/密码；
7. 白名单前缀 `/cities-stores`、`/risk`、`/products`、`/stores`；
8. 删除嵌套 `returnTo`。

### 核心原理

安全校验必须在 URL 规范化之前看到原始输入；规范化会把 `..` 消掉。

### 产物

`lib/navigation.ts`。

### 运行实例

`/cities-stores/../risk` 原始路径含 `..` → 拒绝，回退默认页。

### 遇到的问题

S-01 原实现只检查 `new URL().pathname`，规范化后 `/risk` 通过白名单。

### 验证

`navigation.test.ts` 8 项；`e2e-c1` 非法 returnTo 7 种。

### 下游

所有详情页返回。
