## 1. BI 产品定位与用户角色

### 1.1 产品定位

面向内部经营分析与管理复核的**只读零售经营 BI**：

> 用已验收的 P1–P4 指标，回答“哪里、哪类门店、哪类商品、哪类风险值得复核”，不提供经营评分、门店排名或因果结论。

**不是**：

- 不是实时交易/库存/补货系统；
- 不是 AI Agent/RAG/自动决策系统；
- 不是销售额/GMV/利润分析平台（数据只有归一化销量指数）；
- 不是门店绩效考核或奖惩排名工具。

### 1.2 用户角色

| 角色 | 主要诉求 | 可见范围 |
|---|---|---|
| 经营负责人 | 总览、城市/风险分布 | 总览、城市、风险、报告 |
| 城市/区域运营 | 城市对比、城市内门店画像 | 城市与门店、风险 |
| 门店运营 | 单店档案、同类对比、复核清单 | 门店详情、风险、商品摘要 |
| 商品/品类运营 | SKU 贡献、类别结构、风险商品 | 商品、类别、风险商品 |
| 数据分析师 | 联动筛选、下钻、口径查询 | 全部只读页面 + 指标字典 |
| 数据管理员 | 数据版本、冻结清单、接口状态 | 只读运维/口径页；不提供写入 |

**权限建议**：MVP 采用只读角色配置；不展示真实门店/城市/商品名称；不提供编辑、审批、导出原始明细（仅导出聚合表）。

### 3.5 联动探查 `/explore`

- 顶部全局筛选 + 4 个联动面板：趋势、城市、门店、商品/风险；
- 点击任一图中的城市/门店/类别/风险标签，同步过滤其他面板；
- 表格显示当前筛选下的门店/SKU 聚合；分页；URL 保存筛选状态；
- 下钻路径：城市 → 门店 → 门店详情 → 风险/商品；
- **不提供任意 SQL/公式编辑器**；只提供白名单维度/指标。

### 3.6 方法与口径 `/methodology`

- 统一指标字典 D1–D17（门店率、城市池化、城市门店率均值、门店中位、P90 尾部、零销、CV、R3 等）；
- 样本规则 898/888/10、小城市、n<20、10 家 SKU<10；
- 数据边界：归一化销量指数、无金额/库存/客流/订单/利润、无因果；
- 冻结版本与 manifest、数据表清单；
- 页面中每个指标旁提供“口径”tooltip。

## 4. 前后端技术架构

### 4.1 总体结构

```
React + TypeScript + ECharts
        │ HTTPS / REST
FastAPI（只读 API、参数校验、指标白名单）
        │ SQL（DuckDB，只读）
DuckDB 视图层
        ├─ data/analysis/p1–p4/*.csv
        ├─ data/derived/*.parquet（P1 日/小时/门店日）
        └─ reports/figures（静态图，可选）
```

### 4.2 前端

| 项 | 建议 |
|---|---|
| 框架 | React 18 + TypeScript + Vite |
| 图表 | ECharts（按需引入） |
| 状态 | URL search params 作为筛选真源；React Query 缓存 API 数据；少量 Zustand 存 UI 状态 |
| 路由 | React Router |
| 组件 | 企业级表格、筛选器、Drawer、指标卡、口径 Tooltip |
| 交互 | 图表点击/框选→更新 URL→请求 API；URL 可分享/刷新恢复 |
| 小样本 | 统一 `SuppressedValue` 组件：n<20 显示 `—`，tooltip 说明原因 |
| 可访问性 | 键盘导航、颜色非唯一编码、表格可读 |

### 4.3 后端

| 项 | 建议 |
|---|---|
| 框架 | FastAPI + Pydantic v2 |
| 查询 | DuckDB 只读连接；启动时注册视图；参数化查询 |
| 指标服务 | `metric_catalog` 白名单：字段、口径、表、样本、定义 ID |
| 响应 | `data + meta(n, sample_scope, suppressed, definitions) + warnings` |
| 缓存 | 元数据/字典内存缓存；聚合查询短 TTL；不做实时流 |
| 安全 | 只读；无写接口；CORS 白名单；请求上限/超时 |
| 数据版本 | 读取 P1–P4 `summary.json`/manifest，响应带 `data_version` |

### 4.4 数据层

- 不复制、不改写 P1–P4 原始结果；
- DuckDB 启动时创建只读视图：
  - `v_store_profile` ← P4-A
  - `v_store_diagnosis` ← P4-B
  - `v_store_sku` ← P4-C incidence
  - `v_sku` ← P2 `t1/t9`
  - `v_city` ← P3-A `a1` + P3-D `d5`
  - `v_risk` ← P3-D `d1/d8b/d9/d10`
  - `v_structure` ← P3-C `c1/c8`
  - `v_daily`/`v_hour`/`v_weekday_hour` ← P1/derived
- 若 API 延迟不达标，再增加 **只读 BI mart Parquet**（字段投影/预聚合），仍不改变指标定义；MVP 不默认复制。

### 4.5 Docker Compose

| 服务 | 作用 | 数据 |
|---|---|---|
| `web` | Nginx 托管 React 构建；`/api` 反代 | 无 |
| `api` | FastAPI + DuckDB | 挂载 `../data:/data:ro`，`../reports:/reports:ro` |
| 无数据库服务 | DuckDB 嵌入式只读 | 不新建数据库服务 |

- 数据卷 **read-only**；API 进程无写权限；
- 环境变量：`DATA_ROOT=/data`、`DATA_VERSION`、`CORS_ORIGINS`；
- 不引入 Redis/消息队列/实时流；MVP 不需要。

## 5. API 设计草案

### 5.1 通用约定

- 前缀 `/api/v1`；
- 参数：`city_id`、`store_id`、`quadrant`、`cluster`、`category_l1/l2/l3`、`risk_domain`、`combo_type=exact|at_least`、`sample_scope=all|risk`、`page`、`page_size`、`sort`；
- 响应：

```json
{
  "data": [],
  "meta": {
    "n": 888,
    "sample_scope": "risk",
    "period": "2024-03-28/2024-06-25",
    "metric_ids": ["D1", "D3"],
    "data_version": "p1-p4-freeze-2026-11-08",
    "suppressed": false
  },
  "warnings": []
}
```

- 小样本：`suppressed=true`、统计字段 `null`、`reason="n<20"`；UI 显示 `—`；
- 10 家 SKU<10：`diagnosis_status=not_applicable`，风险字段 null；
- 不使用通用 SQL 查询接口；后端白名单维度和指标。

## 8. 风险、技术难点与验收标准

### 8.1 主要风险

1. **日期筛选误解**：P1–P4 KPI 是 90 天冻结值；任意日期重算会改变指标。方案：KPI 固定 90 天，日期只缩放趋势显示。
2. **小样本泄露**：API/UI 必须双层抑制 n<20；Q2-G1 n=0 真实空单元格；不能在前端自行计算。
3. **指标口径漂移**：D1/D2/D3/D4 易混；所有图表必须带 `metric_id` 和 tooltip，后端白名单。
4. **重复造轮子**：不得重算 P2 SKU 旗标、P3 阈值、P4 共现；BI 只读现有表。
5. **50k store×SKU 性能**：P4-C incidence 50k、pair 1,237；API 分页/预聚合，不把 4.5m 行扫描到前端。
6. **数据版本**：P1–P4 冻结；响应带版本号；禁止写回。
7. **匿名 ID**：不映射真实城市/门店/商品。
8. **数据边界**：不展示 GMV/销售额/利润/库存/客流/留存；不引入 AI Agent/RAG。
9. **图表误导**：不按总量做“经营能力排名”；多风险域不是评分；同店共同出现不是同日。

### 8.2 验收标准

| 类别 | 标准 |
|---|---|
| 数据一致性 | KPI/门店/风险/SKU 与 P1–P4 结果表逐项一致；样本 898/888/10；多风险 132；117/35；1,237 |
| 小样本 | API `suppressed=true`，UI `—`；Q2-G1 n=0；CSV 原始值不直接展示 |
| 下钻 | 城市→门店→门店详情→商品/风险；URL 可分享恢复 |
| 口径 | 每个指标显示定义/样本/期间；D1–D17 字典可查 |
| 边界 | 无 GMV/利润/库存/客流/留存；无因果/评分/排名 |
| 性能（建议） | 总览 P95 API <500ms（本地冻结数据）；表格分页 ≤200；首屏可交互 <2s |
| 保护 | 不读取 eval；不写 P1–P4；Docker 数据卷只读；全量 62 tests 仍通过 |
| 安全 | 只读 API；无 SQL 透传；参数白名单；CORS 限制 |

### 8.3 非目标

- 不做实时数据接入、消息队列、复杂权限/多租户；
- 不做 AI Agent、RAG、自动诊断/自动决策；
- 不做用户留存、利润、库存、客流、订单分析；
- 不重算或改写 P1–P4 指标。

## 9. 方案结论

- BI 可在 P1–P4 冻结成果上直接构建，不需要重复分析；
