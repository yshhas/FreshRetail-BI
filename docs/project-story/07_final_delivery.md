# 第七章 最终交付与整体回顾

## 7.1 项目最终是什么

把整个历程走完，项目最终变成了这样一套东西：

**一套基于 FreshRetailNet-50K 的本地只读零售经营 BI。**

它包含：

- 一层可复现的数据管道：原始 Parquet → 校验 → 清洗 → 聚合 → 分析结果；
- 四层分析：P1 销量、P2 商品、P3 城市/门店/结构/风险、P4 诊断；
- 一套冻结契约：25 个文件、SHA-256、`data_version`；
- 一个只读 API：FastAPI + DuckDB 25 个视图 + 20 个端点；
- 一个前端：React 18 + TypeScript + Vite + ECharts，9 个业务路由；
- 一套测试：pytest 101、vitest 23、Playwright 56；
- 一份运行说明：本地 5173/8000/4173。

它不是一个“什么都有的平台”。它没有：

- 金额/GMV/利润；
- 用户/复购/留存；
- 订单/客流/库存；
- 实时数据；
- AI/预测；
- 登录/权限；
- 公网部署；
- Docker。

这些“没有”，不是遗漏，而是项目边界的一部分。

## 7.3 七个关键转折

### 转折一：从“六模块”到“四模块”

这是项目最重要的一次“减法”。

如果没有这次裁剪，项目会一直停留在“想做但做不了”的状态。裁剪之后，每个保留的模块都能被数据验证。

### 转折二：`sale_amount` 不是金额

这是项目最重要的一次“纠错”。

如果错误没被纠正，后面所有报告、图表、页面都会建立在“销售额”的假叙事上。这次纠错让项目从“看起来完整”变成“至少真实”。

### 转折三：冻结分析结果

这是项目最重要的一次“工程化”。

冻结让 BI 不可能“算出一个和报告不一样的值”。它把“分析”和“展示”真正分开了。

### 转折四：BI 只读，不重算

这是项目最重要的一次“边界设定”。

如果 BI 允许重算，项目就会出现两套口径、两套数字、两套解释。只读让 BI 成为“已验收事实的查询层”，而不是“第二套分析系统”。

### 转折五：审计驱动质量

这是项目最重要的一次“方法升级”。

P2 之后，项目不再依赖“自己跑通”，而是每个阶段都做独立审计。真正严重的问题，几乎都是审计发现的。

### 转折六：URL 状态 + 浏览器历史

这是项目最重要的一次“交互升级”。

它让 BI 从“能看”变成“能顺着问题走，还能回来”。

### 转折七：接受边界

这是项目最重要的一次“成熟”。

项目没有为了“看起来更完整”而硬上 Docker、公网、鉴权、AI。它明确知道自己是什么，也明确知道自己不是什么。

## 7.4 技术决策回顾

| 决策 | 选择 | 关键理由 | 代价 |
|---|---|---|---|
| 数据集 | FreshRetailNet-50K | 中国、真实、2024、CC BY 4.0 | 无金额/用户/订单，仅 90 天 |
| 存储/计算 | DuckDB + Parquet | 单机、分析型、直查 Parquet | 单进程、并发弱 |
| 数据加工 | SQL 聚合 + pandas 后处理 | SQL 减量，pandas 做统计 | 双实现需测试保证一致 |
| 后端 | FastAPI + Pydantic | 契约清晰、自动文档、同语言 | 同步阻塞、并发有限 |
| 前端 | React + TS + Vite + ECharts | 生态成熟、图表全 | 包体积大 |
| 状态 | URL search params | 刷新/分享/前进后退 | 参数校验复杂 |
| 返回 | `returnTo` + 浏览器历史 | 多级返回 + 刷新恢复 | 需要安全校验 |
| 数据边界 | 冻结 + 只读 | 数字可追溯、不可漂移 | 新指标需回分析层 |
| 小样本 | n<20 抑制、SKU<10 不诊断 | 避免误读 | 页面看起来空 |
| 部署 | 本地 127.0.0.1 | 演示足够、无公网风险 | 无容器/无鉴权 |

这些决策没有一个是“唯一正确”的。它们都是在当时的约束下，能接受的选择。

## 7.5 工程复杂度来自哪里

这个项目的复杂度，主要不是“代码量大”。

Python 源约 5,400 行，前端 TS/TSX 约 2,300 行，加起来不到 8,000 行。对一个有 25 个视图、20 个端点、9 个页面的系统来说，这个体量不算大。

真正的复杂度来自四个地方：

### 第一，口径

- 三层销量口径；
- 两种缺货口径；
- 门店率/城市率/池化率；
- 精确/至少；
- 运营域/结构提示；
- 单店日均/单序列日均。

每一个口径错了，都会得到“看起来合理但错误”的结论。

### 第二，小样本

- 10 家 SKU<10；
- n<20 的组统计；
- 共现 <20 店；
- 单店覆盖 n=1 的 SKU。

小样本处理不是一个“if 判断”，而是一套产品规则：哪里显示、哪里置空、哪里提示、哪里不估算。

### 第三，状态

- 筛选、分页、组合在 URL；
- 来源页在 `returnTo`；
- 多级返回在浏览器历史；
- 刷新/直达的降级；
- 非法 URL 的安全校验。

状态管理不是“存一个变量”，而是“在多条路径下都保持一致”。

### 第四，安全

- SQL 注入；
- 路径穿越；
- 开放重定向；
- 参数互斥；
- 空值语义；
- 只读视图；
- 引擎级禁网。

这些不是“加一个中间件”就能解决的，需要在每一层都做对。

## 7.8 如果继续发展，可能走向哪里

以下不是既定计划，只是基于当前结构的技术判断。

### 方向一：演示交付

- Docker Compose：web + api + 只读数据卷；
- 反向代理 + Basic Auth；
- 一键启动脚本。

这是性价比最高的下一步。

### 方向二：工程化

- CI：pytest + vitest + build；
- Playwright 容器化；
- 依赖升级 + 全量回归；
- 日志/指标/健康检查。

### 方向三：数据扩展

- 如果拿到订单/金额/用户数据，可以补客单价、复购、留存；
- 如果拿到更长时间，可以做季节/年度趋势；
- 但必须重新走“口径 → 分析 → 审计 → 冻结”的流程，不能在 BI 层临时加。

### 方向四：产品深化

- `/methodology` 独立页：把指标字典、样本规则、限制集中展示；
- 全局筛选联动；
- 更细的商品下钻；
- 导出能力与页面筛选对齐。

### 方向五：不建议的方向

- 在 BI 层重算指标；
- 为了“看起来完整”而加 AI/预测；
- 在没有鉴权的情况下公网部署；
- 为了消除所有提示而扩大修改范围。

## 7.9 从项目诞生到最终交付：一段完整的回顾

现在把整段历程压缩成一条线：

1. **想法**：做中国数字零售与本地生活的完整经营分析，覆盖企业、用户、商品、区域、诊断。
2. **撞墙**：发现没有任何公开数据能支撑六模块，因为没有订单级、金额级、用户级数据。
3. **选择**：坚持中国定位，选 FreshRetailNet-50K，接受无金额/无用户/90 天的代价。
4. **纠错**：确认 `sale_amount` 是归一化销量，不是金额，项目从“金额分析”转为“销量分析”。
5. **裁剪**：删掉金额、用户、复购、留存，只保留销量、商品、区域、诊断。
6. **打地基**：DuckDB + Parquet + 清洗规则 + 18 项测试。
7. **分析**：P1 销量、P2 商品、P3 城市/门店/结构/风险、P4 诊断。
8. **被审计改变**：分母错配、R² 命名、行序 CI、二次加权、54 家低销、n<20 等问题逐一修正。
9. **冻结**：25 项 SHA，把分析结果变成不可变事实。
10. **产品化**：只读 API + 第一批页面 + 商品 BI。
11. **联动**：URL 状态、返回、多级下钻、精确/至少组合。
12. **验收**：101 pytest、23 vitest、56 E2E、build、25/25 SHA。
13. **停手**：接受“本地可演示，但不是生产系统”的边界。

这条线里没有“灵光一现”的英雄故事，也没有“技术争论”的戏剧性。它更像是一连串很具体的判断：

- 这个字段到底是什么？
- 这个分母该是谁？
- 这个率该怎么聚合？
- 这个缺失该不该补 0？
- 这个空态是“没有”还是“被挡住”？
- 这个 URL 能不能信？
- 这个返回该用参数还是历史？
- 这个功能该不该做？

每一个判断都不大，但它们叠加起来，决定了项目最终的样子。

## 7.10 结语

这个项目最值得记录的地方，不是它用了 DuckDB、FastAPI 或 React。

而是它在资源有限、数据不完美的情况下，始终坚持了三件事：

1. **不把没有数据支撑的需求写成结论**；
2. **不把“跑通”当成“正确”**；
3. **不把“看起来完整”当成“可以交付”**。

它也有很多没做好的地方：没有 Git、没有 CI、没有 Docker、没有鉴权、依赖漏洞未升级、包体积偏大、部分文档数字不一致。

但这些“没做好”并没有被隐藏，而是被写进了报告、技术债和限制说明里。

如果说这个项目给后来者留下什么经验，大概就是：

> 数据分析项目的核心不是“算出数字”，而是“让每个数字都能被解释、被追溯、被复现，并且在被误解之前主动说明它的边界”。

这句话，贯穿了从 01 到 09 的全部阶段，也贯穿了这部纪实。
